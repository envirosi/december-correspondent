# Railway build handoff

## Screens and permissions
1. **Invitation.** Editor imports the roster, generates one expiring, single-use invitation per person and distributes individually. Invite opens a confirmation screen. Redeem on an explicit button press so an email link preview cannot consume it. Exchange the token for a persistent secure session. Editor can revoke or reissue a link for a new device. Store token digests. Keep tokens out of logs.
2. **Front page.** Today’s shared door, archive grid, optional submissions and links to Pigeonhole and Diplomatic Pouch. Show a welcome edition before December and the complete archive after 24 December. Preload only released body text. In mixed-time-zone discussions, show replies only to readers who can open the parent door.
3. **My pigeonhole.** Show the reader’s own 24 doors. Each combines its base entry with any editor-added item addressed to that person and date. Personal letters and parcels have their own headings. The base entry always works if the envelope is empty. Allow people to revisit opened doors. Acknowledging or replying is optional.
4. **Diplomatic Pouch.** Separate opt-in, interests and withdrawal button before draw. Draw once after the cut-off. Shuffle enrolled readers securely into a ring and assign each to the next, including the last to the first. Fewer than two entrants means defer and notify the editor. Freeze assignments transactionally with unique giver and recipient per edition. A repeat press returns the existing draw. Each giver sees only their recipient and interests. Save or edit a draft consisting of text plus an optional HTTPS link. Preview and seal it. Show delivery date on sealing. If someone withdraws after the draw, editor arranges a reserve parcel privately without redrawing. Reveal gifts in recipients’ pigeonholes on their local delivery date, or immediately if sealed later. Default to anonymous delivery. Reader may request publication of their own parcel, subject to permission for any named people.
5. **Letters to the editor.** On eligible shared doors, accept one short text contribution and optional media link. For launch, use links for songs, photos, audio and GIFs. Include a description for media. Opt in explicitly to newsroom publication and choose a byline or “A reader”. Drafts stay off the front page. Editor approves or declines, can unpublish, and can attach an approved contribution to a later door for the relay or finale.
On day 14, replace the public contribution form with a private letter form: choose recipient, write note, choose signature. Save directly as a personal item for that reader on the current released day; omit from the moderation feed. On day 18, link to the pigeonhole instead of displaying a reply form.
6. **Editor’s Desk.** Edit and preview both editions by date and region, import readers, issue invites, add private letters, check who still needs a note, review contributions, trigger the draw and see which recipients need a reserve. Editor preview is a separate, labelled mode. Use an explicit confirmation for the draw button (“Draw names now?”). Leave everyone’s reading habits out of this screen.

## Implementation contract
Use a single Railway web service backed by PostgreSQL. Keep all edition content and staff data server-side. Use an environment-provided database URL, session secret and trusted public origin. Serve a health endpoint. Run versioned migrations and an idempotent seed keyed by edition and day. Reimporting the CSV requires an explicit editorial overwrite for existing edited doors. Static assets may be cached publicly. Personal responses require private, no-store caching. Validate role, membership, release time and ownership on each request. Escape contributed text, validate link schemes and display the destination before opening a media link.

Suggested records: edition (year and draw instant), reader (edition, stable ID, name, unique work email, zone, role), invitation/session (reader, digest, expiry, revocation), door (edition/day, shared and private copy), personal_item (recipient, day, text, optional URL, byline), contribution (author, source day, display day, text, media description, consent, chosen byline, moderation state), enrolment (reader, wishes), assignment (edition, giver, recipient), parcel (assignment, text, URL, draft/sealed, delivery day). Restrict editor routes separately. Import letters by matching recipient email and reject unmatched or ambiguous rows with a row number. Offer an import preview before committing.

Use Europe/London, Asia/Manila and Australia/Sydney. Release both doors at 07:00 on the numbered local date as evaluated on the server. Before 07:00 keep yesterday’s edition available. Pouch enrolment closes at one shared instant, 09:00 UTC on 8 December. Display it in each reader’s zone. Door release requires no midnight background job.

## Rehearsal before issuing invitations
- At 20:00 UTC on 30 November Sydney can open door 1. Cebu and UK still see the welcome edition. Cebu unlocks at 23:00 UTC and UK at 07:00 UTC on 1 December.
- Reader A can reopen their letter on a phone. Reader B gets denied for A’s letter and parcel even with the item address. Future text is absent from the page and API responses.
- A reader who skips Santa still sees their calendar. Test the draw with zero, one, two and five entrants. Two simultaneous draw requests produce one set of assignments, with no self-match.
- Test the release boundary on gift day, a late gift, a replacement invite, an unapproved caption and an editor unpublishing an approved caption.
- Test keyboard-only navigation, enlarged text, a text-only parcel and a narrow phone. Reopen a December door in January. Confirm a service restart preserves invitations, assignments, letters and submissions.

## Agreed changes (26 November)
- Relay doors (3, 17, 21): a consented contribution publishes immediately so the next desk can pick it up. The editor can unpublish.
- Day 14 private letters go to the editor for a check before they reach the recipient's pigeonhole. They stay out of the public moderation feed.
- Delivery is staged: doors and Pouch enrolment by 1 Dec, draw and parcels by 8 Dec, day-14 letters by 14 Dec, gift delivery by 18 Dec.
- Retention: the paper closes on 31 January 2027 and a purge command deletes all personal data.
